# The CV

Local only. `app/cv/page.tsx` is gitignored and never deployed.

## Editing

Career facts live in `lib/data.ts` — edit there, not in the page. The page owns
layout only.

    npm run cv        # build + render cv.pdf + check for clipping

`cv.pdf` lands in the repo root and is gitignored.

## Exporting from the browser

Open `/cv` and press **Save as PDF**. In the print dialog choose **A4** and set
margins to **None** — the sheets carry their own padding, and dialog margins
would shrink them and add white edges.

## Two fixed sheets, not a flowing document

The CV is two fixed 297mm sheets rather than one document that flows across
pages. This is deliberate:

An edge-to-edge sidebar requires `@page { margin: 0 }`. But that also removes the
top margin from *continuation* pages, so a flowing document gets its text sliced
at the page boundary with no breathing room. Fixed sheets each carry their own
padding and their own sidebar, so both pages are correct.

The cost is that content must be assigned to a sheet by hand.
`ROLES_ON_SHEET_ONE` in `app/cv/page.tsx` controls the split.

## The sidebar tint is an image, not a background

Chrome's print dialog has a **Background graphics** checkbox that is off by
default and silently drops CSS backgrounds. The sidebar tint is therefore an
inline SVG `<img>`, which the dialog cannot drop. `scripts/render-cv-pdf.mjs`
runs with `printBackground: false` on purpose, so the worst case is what gets
tested on every render.

## Clipping

A fixed-height sheet with `overflow: hidden` clips silently — the exact failure a
PDF hides from you. `render-cv-pdf.mjs` measures each sheet and **exits non-zero**
if content overflows. If it fails, either tighten `.cv-compact` in
`app/globals.css` or move a role across the sheet boundary.

Adding bullets to `lib/data.ts` is the usual cause.
